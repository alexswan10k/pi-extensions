### Architecture & Mechanics

1. **Default-On Compaction, Opt-In Goal & Wake**
   - On `session_start`, the extension loads `.pi/memory/<sessionId>.json`; a fresh session starts with compaction **enabled**. `self_compact` and `memory_store` are declared by default; `goal_set` and `wake_defer` are stripped from active tools until their owner opts in (saving schema tokens for the common case). `/self-propagate off` is the escape hatch: all hooks no-op and every tool is hidden until `on`.
   - Compaction survives `/reload` and `--resume` via the persisted `enabled` flag. Legacy files that explicitly set `enabled: false` stay off; files without the flag get the new default.
   - **DX:** bare `/self-propagate` (or `/self-propagate help`) prints full usage plus the current state. Plain `on` only re-enables after `off` — it never creates a goal. `on here` is the explicit goal opt-in: it seeds from the latest user message and (interactively) offers keep / edit / skip. `/self-propagate status` renders a budget progress bar, the goal, the anchor, KV usage and timers. Subcommands and their arguments tab-complete; unknown subcommands fail with a pointer to `help`.
2. **Model-Relative Context Budget & 2-Turn Grace Lock**
    - Uses `ctx.getContextUsage()` to read the active model's native `contextWindow` and authoritative token count (including system prompt and tool schemas).
    - **Cache-clean by construction:** the system prompt only ever gets the static `## Self-Propagation & Context Protocol` block — byte-identical every turn and across compactions (pi's forced prompt is re-sent every request; any byte that differs costs the whole prompt). The one model-dependent byte is the numeric ceiling line (e.g. `100k tokens (50% of the 200k-token window)`, which also tells the agent that pi's own context bar uses the full window, not the budget), and it changes only on a model switch or `/self-propagate budget` — both already rebuild the prompt. The volatile budget alert is delivered as a `<self_propagate_budget level="notice|warning|critical">` custom message in the run's starting messages — it re-reads nothing before it, and appears only at ≥50%.
     - **Headroom Buffer:** Because hitting 100% of the *physical* model window would cause the LLM provider to reject the grace turns with `context_length_exceeded`, the extension defines your **Effective Budget Ceiling** as `65%` of `ctx.model.contextWindow` by default (configurable via `/self-propagate budget <0.30-0.95>`). On a 200k model that means notice at 65k, warning at 97.5k and critical at 130k tokens of actual usage.
    - **Tiered escalation against Effective Budget:**
      - **50%:** One-line telemetry notice appended to tool results.
      - **75%:** `<self_propagate_budget level="warning">` injected into the turn context + wrap-up warning in tool results.
       - **100% (Turns 1–2):** Increments `overBudgetTurns` on each `before_agent_start` and injects an urgent `<self_propagate_budget level="critical"> [CRITICAL CONTEXT ALERT — ... GRACE TURN X/2]` message plus escalation in every tool result.
       - **100% (Turn 3+):** Hard-blocks all tool calls in `tool_call` except `self_compact` and `memory_store`.
3. **Full-Wipe Compaction + Pinned Context + Continuation**
     - When the agent calls `self_compact({ summary, keepFirstTurns, continueAfter, nextObjective, memoryUpserts })`:
       - Any further tool calls in the same turn are blocked so the turn settles cleanly.
       - On `agent_end`, the queued checkpoint is applied as a **cut**: the extension computes the visible-message count and anchor of the current branch, persists `{ checkpoint, prefixCount, anchorRole, anchorSample, createdAt }` in `.pi/memory/<session>.json`, and (best-effort) appends a custom `self_propagate_checkpoint` audit entry. **No pi compaction entry is ever written — `ctx.compact()` is not called.** From then on the `context` hook (fired before every provider request) returns `[checkpoint as a compactionSummary] + messages since the cut`, verbatim. The transcript file and the TUI are untouched; only the model's window shrinks.
        - The **session goal is optional**. When set, it is baked into the checkpoint at the top (`<pinned_context source="..." updated="...">`), followed by `<working_memory>` and `<compaction_summary>`. With no goal, the checkpoint starts at `<working_memory>` — no empty marker, no mandate. Each goal is capped at **12,000 chars** (~3k tokens).
        - **The goal is a persisted document, not a re-extraction, and it is opt-in.** It lives in `.pi/memory/<session>.json` (`pinnedContext: { text, source, updatedAt }` plus a `goalSeedRequested` flag). Fresh sessions have neither: no goal, no nudge, no `goal_set` tool. You opt in with `/self-propagate on here` (seed from the latest user message, interactively kept/edited/skipped), `goal set <text>`, `goal here`, `goal reset` (seed from the session root or the stored `anchorEntryId` at the next checkpoint), or `goal draft`. Only then does seeding happen; `skip` and `goal clear` leave no goal at all and never re-seed lazily. The seed keeps between `minPinnedTurns` (default **1**) and `MAX_PINNED_TURNS` (**4**) turns of history, clamped per turn at 12,000 chars. If the anchor no longer resolves on the branch (e.g. after tree navigation), the seed falls back to the session root and a warning is shown. Once set, the goal is re-injected **verbatim**; `keepFirstTurns` only steers the seed, it does not re-extract. There is no per-turn "propose a goal" nudge.
               - **Changing the goal requires the user, always.** Once a goal is opted into, the agent may *propose* a change via the `goal_set` tool (`text`, `reason`) — the proposal goes through `ctx.ui.confirm(...)` (2000-char-truncated preview in the dialog, 12,000-char hard cap on the goal) and applies only with user approval. The user can also change the goal directly: `/self-propagate goal show|set|clear|reset|here|draft`. `goal clear` renders `<pinned_context status="empty" source="..." />` (deliberately no mandate); `goal reset` discards the custom goal and re-seeds from the branch at the next checkpoint; `goal here` pins the latest user message as the goal; `goal draft` asks the agent to propose a change via `goal_set` (blocked while a compaction is queued or in flight). There is no agent-side path around the gate.
       - **Goal changes take effect at the next compaction** — rendered live from the memory file at compaction time, so a goal set seconds before `agent_end` (even during a queued compaction) is what gets baked in. `goal_set` is blocked while a compaction is queued or the hard lock is engaged; the user-facing `goal set` is not.
       - **Pi-native compactions lose the mandate.** The extension cancels pi's `threshold` compactions unconditionally — its own checkpoint path no longer goes through pi at all. Pi's default `/compact` (manual) and `overflow` (API `context_length_exceeded`) paths still fall through to pi's built-in summarizer, which knows nothing of the goal — no `<pinned_context>`, no `<working_memory>`, no agent summary re-injected. A pi CompactionEntry also breaks the cut's anchor verification (the added summary message shifts `prefixCount`), so elision drops conservative-style: the checkpoint is prepended, the full history flows, and the cut is cleared — the grace-lock escalation exists to make the overflow case improbable.
       - **Cache semantics:** writing the goal to the file never enters context and never busts the cache. Goal edits take effect at the *next* compaction — piggybacking on the full-prefix miss compaction already causes. To apply a goal change immediately, run `/self-propagate compact`, which asks the agent to `self_compact` right away. A manual compaction costs exactly the same full-prefix cache miss as any trigger — never cheaper, but at low budgets it is nearly free in dollars, and at high budgets you would compact soon anyway.
       - If `continueAfter: true`, the agent_end cut dispatches `pi.sendUserMessage(..., { deliverAs: "steer" })` to immediately resume work on `nextObjective`.
       - **The cut is verified on every request, not trusted.** Before eliding, the `context` hook checks that `messages[prefixCount - 1]` still matches the stored anchor (role + trailing 200 chars, mirroring pi's projection rules: `message`/`custom_message`/`branch_summary`/`compaction` entries each produce one visible non-system message). If the branch no longer lines up — fork, tree navigation, `context_edit` — nothing is dropped: the checkpoint still rides the head of the request, the cut record is **dropped** (a fresh `self_compact` re-establishes elision), and the user gets a one-time warning. Dropping live messages is never the failure mode; at worst the elision is lost and the full history flows again.
4. **Capped Title + Body KV Store (**`.pi/memory/<sessionId>.json`**)**
   - Each entry stores `{ key, title, body, updatedAt }` with strict caps: max **25 entries**, `key <= 48` chars, `title <= 100` chars, `body <= 1,200` chars, and **16,000 chars total store size**.
   - Exposed via a single `memory_store` tool (`upsert`, `delete`, `search`, `list`) and inline `memoryUpserts` inside `self_compact`.
5. **Idle Nudge (default) vs Opt-In Keep-Awake**
    - A `globalThis` singleton timer (preventing duplicate loops on `/reload`) is installed only when `enabled` and a wake mode is configured. It fires only when `!isBusy && !isCompacting && !pendingCompaction`.
    - `/self-propagate wake once <minutes>` is the **default at 45 minutes** (the old `idle` command). Once per idle streak (`idleCompactWarned`), and only when the prefix is over the reclaim gate (25k tokens, or 5k above the measured post-compact floor), it wakes the agent with a `<keep_awake_tick pressure="1">` steer to persist notes and run `self_compact({ continueAfter: false })`. A session already at the floor is left alone — sleeping there is cheap. `0` disables the nudge.
    - `/self-propagate wake every <minutes>` is the **opt-in repeating cron**: every $X$ minutes idle the agent receives a keep-awake tick and keeps working (with the same pressure check). When set, it takes precedence over `once`. The cron is deliberately opt-in so Orca bots keep their own wake events in charge of ordinary idle activity.
    - `/self-propagate wake off` clears both modes and any active deferral; `wake` with no subcommand shows both plus the deferral.
   - `wake_defer` (tool, agent-side): silences **all** wake modes for N minutes — **any duration is allowed** (`wake_defer({ minutes: 300 })` is fine), or `0` to clear early. The local-model cache rule is enforced *at deferral time*: the local KV cache has **no TTL** — other local sessions evict it via memory pressure within ~10-15m of silence, and a bust re-reads the whole prefix. So when the prefix is **25k+ tokens — or 5k+ above the post-compact floor, if that is larger** (the smallest prefix the session can have: system + tools + checkpoint; self-measured after each checkpoint is applied, bootstrapped 20k, measured ~20.7k in the live session, reset on model switch), the tool **auto-queues a shrink checkpoint first** — applying the same cut the agent's own `self_compact` would, one planned, controlled cache bust at a known moment, then the session sleeps on a minimal prefix. At the floor, no compaction — sleeping is cheap. If the agent already called `self_compact` this turn, its summary wins and nothing is queued. The deferral is persisted (survives restarts), shown in the footer as `⏸Nm` and in `status`, is respected by both wake modes, and is cleared by any explicit `wake …` configuration from the user.
   - `/self-propagate compact` sends a `<force_compact>` steer on demand: the agent persists critical notes and calls `self_compact` (same discipline as the once-mode path). It is a full-prefix cache miss like any compaction; there is no way around that, but it makes goal pivots effective now rather than at the next natural compaction.
6. **Durability Across Restarts**
    - Everything durable lives in `.pi/memory/<sessionId>.json` (atomic tmp-file + rename on every mutation): `enabled` (default `true`), `budgetRatio` (default `0.65`), `keepAwakeMinutes` (default `0`), `idleCompactMinutes` (default `45`), `minPinnedTurns`, `anchorEntryId`, `goalSeedRequested`, `pinnedContext`, the KV store, and — so a restart cannot escape them — the grace counter `overBudgetTurns`, the idle-wake latch `idleCompactWarned`, and any `pendingCompaction` queued by `self_compact`.
       - Legacy files without `graceTurns` / `idleCompactMinutes` keep the old values (**5** grace turns, **15m** idle nudge); every newly written file pins the new defaults (2 / 45m), so later sessions get the aggressive behavior.
    - On `session_start` the file is reloaded. A checkpoint queued before the process died (between `self_compact` and `agent_end`) is restored, tool calls stay blocked, and it is executed at the next turn end — the agent resumes with the checkpoint summary instead of silently unbounded growth.
   - Never persisted: `isBusy` / `isCompacting` (an interrupted compaction is always safely retriable) and the idle clock (reset at every `session_start`).
   - State is cwd-scoped: resuming the session file from a *different* working directory starts from a fresh memory file by design.
    - A corrupt memory file degrades to safe defaults (compaction on, no goal, no repeating cron, 45m idle nudge), never to a crash or a half-loaded state.
   - Covered by `extensions/self-propagate.test.mjs` (boot → kill → reboot against the same workspace, plus the goal lifecycle: seed → user override → agent rewrite approve/reject → clear → reset, and the interactive enable-time flow (keep/edit/skip)), wired into `npm test`.

### Tooling Surface

- **Commands:** a single entry point, `/self-propagate` (bare = help + current state): `on [here]` · `off` · `status` · `budget <0.3-0.95>` · `wake <once|every> <minutes>` · `wake off` · `goal [show|set|clear|reset|here|draft]` · `compact` · `help`. Subcommands and arguments tab-complete. One wake concept, two strengths: `once` (default 45m) fires a shrink steer once per idle streak when the prefix is over the reclaim gate, `every` is the opt-in repeating cron (same pressure check); `wake every` takes precedence.
- **Cache economics (local models).** Every byte of the request head (system prompt + tool schemas) that changes busts the prefix cache — on local Apple-Silicon inference a cold re-read of the current prefix is minutes of compute, so the design minimizes head churn: the protocol block is static apart from the ceiling line (model/budget switches only), volatile budget telemetry rides per-turn appended messages, compaction is a full-wipe whose only new bytes are the agent's own checkpoint, and any sleep happens on a prefix at or below floor+5k (wake_defer auto-shrinks otherwise), so an eviction mid-sleep is a cheap re-read. The remaining intentional busts: tool set on enable/disable/goal-wake-opt-in, each compaction's new summary, and the one *planned* bust a long deferral triggers when the prefix is fat. Telemetry stays lean on purpose: messages exist only at tick-fires and tool calls (1-2 lines each) — never per-turn bloat.
- **Tools:** `self_compact`, `memory_store` — declared by default with compaction. `goal_set` appears only after a goal opt-in; `wake_defer` appears whenever a wake mode is configured (including the 45m default nudge). `goal_set` is hard-blocked like the other tools while a compaction is queued or the grace lock is engaged, and every applied goal change requires explicit user confirmation. `wake_defer` is the one tool the agent can use on the wake watchdog; it never changes the user's configured cadence, only silences it until the deferral expires or the user re-configures.
- **Renaming:** the extension used to ship `/propagate`, `/keep-awake`, `idle` and the `pin` subcommand; they are now subcommands of `/self-propagate` (`wake every` / `wake once` / `goal` respectively). Old command names no longer resolve. The internal checkpoint tag remains `<pinned_context>` (an internal wire format, renamed concept only).

### Why Pi's own system prompt needs no pinning (and where the cache really goes)

**How pi handles the prompt across compaction.** Pi rebuilds the system prompt from *current* resources on every run and diffs it against the sections recorded in the transcript; changed or removed sections are patched in as system messages, and system messages before any kept range are dropped at compaction (a fresh snapshot is replayed via the compaction entry). Extension/tool changes flow through the same diff (`toolsAdded`/`toolsRemoved`), and the loadout is restored from the branch on resume. Reloading an old session therefore picks up the new pi prompt, new extensions and new tools automatically.

**What the cut costs in the cache — exactly.** The cut is implemented as a per-request elision, not as a session rewrite: pi sends system prompt + tools + messages, and the `context` hook replaces the pre-cut body with one `compactionSummary` message carrying the checkpoint. Prompt caches are prefix-based, so the parts of the request *before* the first differing byte survive: with a stable head, the tool schemas + system prompt stay cached across the cut, and the cache diverges at the checkpoint summary. The unavoidable loss: the entire pre-checkpoint conversation body is replaced, so everything after the system block is a fresh read — true of *any* compaction, including pi's built-in one (which is actually *luckier*: it keeps the most recent ~20k tokens verbatim, pushing the divergence point further right and preserving more prefix). A full-wipe cut can never do better by construction; the only honest levers are keeping the head byte-stable — that is why the extension protocol block is a constant and all volatile budget telemetry is delivered as per-run custom messages — and keeping the anchor verification cheap (a single endsWith over the anchor message per request).

**Things the agent should know, verified against pi 1.5.2 source:**

- Pi's built-in summarizer is bypassed for `self_compact` checkpoints (`fromExtension: true`); it is also separately cache-safe when it does run: the summary request uses its own `SUMMARIZATION_SYSTEM_PROMPT`, the conversation as a single serialized user message, and `cacheRetention: "none"` (one-off prompts never write prompt cache). The session prompt is never touched by it.
- The summarization call uses the session's own model (`this.model` via the same auth chain), not a separate utility model — unless you configure pi's virtual-model routing, in which case it resolves a physical model from the virtual selection.
- Pi's `/compact` and overflow recovery use the same machinery; the extension cancels `threshold` compactions with no pending checkpoint but cannot intercept a manual `/compact` or an `overflow` — both lose the goal, KV and agent summary (documented in §3).
- Reloading a session against a *different* pi version or extension set: the head changes once (sections diff), everything re-caches, and it is stable again thereafter. Sections-diff patches keep mid-conversation-system-message models' cached prefix; models without that get one replay miss per *change* (not per turn).

**What the session file keeps.** Everything: `messages`, `compaction`, `context_edit`, model/thinking-level changes. Diffing/review tooling on the raw file sees the pre-compaction history forever; the checkpoint is additive metadata, not a splice.

**What self-propagate freezes, and what it scrubs.** Self-propagate checkpoints freeze up to three things: the session goal (when opted into), the KV working memory and the agent's summary — all agent- or user-authored, all explicit. Pi's system prompt is never frozen. Agent/user content that enters the checkpoint is scrubbed of checkpoint- and steering-shaped tags (`<pinned_context>`, `<working_memory>`, `<compaction_summary>`, `<note>`, `<self_propagation_compaction_failed>`, etc.) on the write paths (goal set/seed/`goal_set`) and again at render time (KV bodies/titles, summary), so forging a checkpoint or a fake failure notice from inside the session means getting the user to approve literally that text. The remaining soft spots are cosmetic at worst: `budgetRatio` and other hand-edited scalars are not range-validated on load, and there is no append-only audit log of mandate rewrites yet.
