### Architecture & Mechanics

1. **Opt-In Session Gate (**`/self-propagate on`**)**
   - **Zero overhead when off:** On `session_start`, the extension checks `.pi/memory/<sessionId>.json`. If the session has not opted in, `pi.setActiveTools()` strips `self_compact`, `memory_store` and `goal_set` from the active tool declarations (saving schema tokens) and all lifecycle hooks no-op.
   - Running `/self-propagate on` enables the extension for the current session, persists the flag to `.pi/memory/<sessionId>.json` (surviving `/reload` and `--resume`), and activates the tools and background watchdog.
   - **DX:** bare `/self-propagate` (or `/self-propagate help`) prints full usage plus the current state; `/self-propagate on` seeds the **session goal** explicitly and (interactively) asks you to keep, edit or skip it: turn 1 by default, the latest user message for `on here`. `/self-propagate status` renders a budget progress bar, the goal, the anchor, KV usage and timers. Subcommands and their arguments tab-complete, unknown subcommands fail with a pointer to `help`, and `/self-propagate on here` re-anchors mid-session (affecting only the goal *seed* — see §3).
2. **Model-Relative Context Budget & 5-Turn Grace Lock**
    - Uses `ctx.getContextUsage()` to read the active model's native `contextWindow` and authoritative token count (including system prompt and tool schemas).
    - **Cache-clean by construction:** the system prompt only ever gets the static `## Self-Propagation & Context Protocol` block — byte-identical every turn and across compactions (pi's forced prompt is re-sent every request; any byte that differs costs the whole prompt). The one model-dependent byte is the numeric ceiling line (e.g. `100k tokens (50% of the 200k-token window)`, which also tells the agent that pi's own context bar uses the full window, not the budget), and it changes only on a model switch or `/self-propagate budget` — both already rebuild the prompt. The volatile budget alert is delivered as a `<self_propagate_budget level="notice|warning|critical">` custom message in the run's starting messages — it re-reads nothing before it, and appears only at ≥50%.
     - **Headroom Buffer:** Because hitting 100% of the *physical* model window would cause the LLM provider to reject the 5 grace turns with `context_length_exceeded`, the extension defines your **Effective Budget Ceiling** as `85%` of `ctx.model.contextWindow` by default (configurable via `/self-propagate budget <0.30-0.95>`).
    - **Tiered escalation against Effective Budget:**
      - **50%:** One-line telemetry notice appended to tool results.
      - **75%:** `<self_propagate_budget level="warning">` injected into the turn context + wrap-up warning in tool results.
      - **100% (Turns 1–5):** Increments `overBudgetTurns` on each `before_agent_start` and injects an urgent `<self_propagate_budget level="critical"> [CRITICAL CONTEXT ALERT — ... GRACE TURN X/5]` message plus escalation in every tool result.
      - **100% (Turn 6+):** Hard-blocks all tool calls in `tool_call` except `self_compact` and `memory_store`.
3. **Full-Wipe Compaction + Pinned Context + Continuation**
     - When the agent calls `self_compact({ summary, keepFirstTurns, continueAfter, nextObjective, memoryUpserts })`:
       - Any further tool calls in the same turn are blocked so the turn settles cleanly.
       - On `agent_end`, the queued checkpoint is applied as a **cut**: the extension computes the visible-message count and anchor of the current branch, persists `{ checkpoint, prefixCount, anchorRole, anchorSample, createdAt }` in `.pi/memory/<session>.json`, and (best-effort) appends a custom `self_propagate_checkpoint` audit entry. **No pi compaction entry is ever written — `ctx.compact()` is not called.** From then on the `context` hook (fired before every provider request) returns `[checkpoint as a compactionSummary] + messages since the cut`, verbatim. The transcript file and the TUI are untouched; only the model's window shrinks.
       - The **session goal** is baked into the checkpoint at the top (`<pinned_context source="..." updated="...">`), followed by `<working_memory>` and `<compaction_summary>`. Each seed is capped at **12,000 chars** (~3k tokens), as is any custom goal.
       - **The goal is a persisted document, not a re-extraction.** It lives in `.pi/memory/<session>.json` (`pinnedContext: { text, source, updatedAt }`) and is set **at enable time** — seeded from the session root, or from the latest user message with `/self-propagate on here` (anchor entry id stored as `anchorEntryId`), then interactively confirmed (keep / edit / skip; headless keeps the seed). The seed keeps between `minPinnedTurns` (default **1**) and `MAX_PINNED_TURNS` (**4**) turns of history, clamped per turn at 12,000 chars. If the anchor no longer resolves on the branch (e.g. after tree navigation), the seed falls back to the session root and a warning is shown. If enable-time seeding was skipped, the goal seeds lazily at the first self-propagate checkpoint instead. Chose `skip`? That stores a deliberately-empty user goal — no lazy re-seed ever resurrects it. From then on the goal is re-injected **verbatim**; `keepFirstTurns` only steers the seed, it does not re-extract. A goal-less session's agent is nudged every turn to propose one via `goal_set`.
       - **Changing the goal requires the user, always.** The agent may *propose* a change via the `goal_set` tool (`text`, `reason`) — the proposal goes through `ctx.ui.confirm(...)` (2000-char-truncated preview in the dialog, 12,000-char hard cap on the goal) and applies only with user approval. The user can also change the goal directly: `/self-propagate goal show|set|clear|reset|here|draft`. `goal clear` renders `<pinned_context status="empty" source="..." />` (deliberately no mandate); `goal reset` discards the custom goal and re-seeds from the branch at the next checkpoint; `goal here` pins the latest user message as the goal; `goal draft` asks the agent to propose a change via `goal_set` (blocked while a compaction is queued or in flight). There is no agent-side path around the gate.
       - **Goal changes take effect at the next compaction** — rendered live from the memory file at compaction time, so a goal set seconds before `agent_end` (even during a queued compaction) is what gets baked in. `goal_set` is blocked while a compaction is queued or the hard lock is engaged; the user-facing `goal set` is not.
       - **Pi-native compactions lose the mandate.** The extension cancels pi's `threshold` compactions unconditionally — its own checkpoint path no longer goes through pi at all. Pi's default `/compact` (manual) and `overflow` (API `context_length_exceeded`) paths still fall through to pi's built-in summarizer, which knows nothing of the goal — no `<pinned_context>`, no `<working_memory>`, no agent summary re-injected. A pi CompactionEntry also breaks the cut's anchor verification (the added summary message shifts `prefixCount`), so elision drops conservative-style: the checkpoint is prepended, the full history flows, and the cut is cleared — the grace-lock escalation exists to make the overflow case improbable.
       - **Cache semantics:** writing the goal to the file never enters context and never busts the cache. Goal edits take effect at the *next* compaction — piggybacking on the full-prefix miss compaction already causes. To apply a goal change immediately, run `/self-propagate compact`, which asks the agent to `self_compact` right away. A manual compaction costs exactly the same full-prefix cache miss as any trigger — never cheaper, but at low budgets it is nearly free in dollars, and at high budgets you would compact soon anyway.
       - If `continueAfter: true`, the agent_end cut dispatches `pi.sendUserMessage(..., { deliverAs: "steer" })` to immediately resume work on `nextObjective`.
       - **The cut is verified on every request, not trusted.** Before eliding, the `context` hook checks that `messages[prefixCount - 1]` still matches the stored anchor (role + trailing 200 chars, mirroring pi's projection rules: `message`/`custom_message`/`branch_summary`/`compaction` entries each produce one visible non-system message). If the branch no longer lines up — fork, tree navigation, `context_edit` — nothing is dropped: the checkpoint still rides the head of the request, the cut record is **dropped** (a fresh `self_compact` re-establishes elision), and the user gets a one-time warning. Dropping live messages is never the failure mode; at worst the elision is lost and the full history flows again.
4. **Capped Title + Body KV Store (**`.pi/memory/<sessionId>.json`**)**
   - Each entry stores `{ key, title, body, updatedAt }` with strict caps: max **25 entries**, `key <= 48` chars, `title <= 100` chars, `body <= 1,200` chars, and **16,000 chars total store size**.
   - Exposed via a single `memory_store` tool (`upsert`, `delete`, `search`, `list`) and inline `memoryUpserts` inside `self_compact`.
5. **Wake Watchdog — `once` vs `every`**
   - Managed by a `globalThis` singleton timer (preventing duplicate loops on `/reload`) that only fires when `enabled && !isBusy && !isCompacting`.
   - `/self-propagate wake every <minutes>` makes idle sessions receive a `<keep_awake_tick>` steer message every $X$ minutes (auto-enables self-propagation).
   - `/self-propagate wake once <minutes>` (the old `idle` command) instead fires **once per idle streak**, and only when context usage $\\ge 25\\%$ of budget: it wakes the agent once (`idleCompactWarned = true`) to persist notes and run `self_compact({ continueAfter: false })`. `wake once` only applies when `wake every` is 0.
   - `/self-propagate wake off` clears both wake timers and any active deferral; `wake` with no subcommand shows both plus the deferral.
   - `wake_defer` (tool, agent-side): silences **all** wake modes for N minutes — **any duration is allowed** (`wake_defer({ minutes: 300 })` is fine), or `0` to clear early. The local-model cache rule is enforced *at deferral time*: the local KV cache has **no TTL** — other local sessions evict it via memory pressure within ~10-15m of silence, and a bust re-reads the whole prefix. So when the prefix is **25k+ tokens — or 10k+ above the post-compact floor, if that is larger** (the smallest prefix the session can have: system + tools + checkpoint; self-measured after each checkpoint is applied, bootstrapped 20k, measured ~20.7k in the live session, reset on model switch), the tool **auto-queues a shrink checkpoint first** — applying the same cut the agent's own `self_compact` would, one planned, controlled cache bust at a known moment, then the session sleeps on a minimal prefix. At the floor, no compaction — sleeping is cheap. If the agent already called `self_compact` this turn, its summary wins and nothing is queued. The deferral is persisted (survives restarts), shown in the footer as `⏸Nm` and in `status`, is respected by both wake modes, and is cleared by any explicit `wake …` configuration from the user.
   - `/self-propagate compact` sends a `<force_compact>` steer on demand: the agent persists critical notes and calls `self_compact` (same discipline as the once-mode path). It is a full-prefix cache miss like any compaction; there is no way around that, but it makes goal pivots effective now rather than at the next natural compaction.
6. **Durability Across Restarts**
   - Everything durable lives in `.pi/memory/<sessionId>.json` (atomic tmp-file + rename on every mutation): `enabled`, `budgetRatio`, `keepAwakeMinutes`, `idleCompactMinutes`, `minPinnedTurns`, `anchorEntryId`, `pinnedContext`, the KV store, and — so a restart cannot escape them — the grace counter `overBudgetTurns`, the idle-wake latch `idleCompactWarned`, and any `pendingCompaction` queued by `self_compact`.
   - On `session_start` the file is reloaded. A checkpoint queued before the process died (between `self_compact` and `agent_end`) is restored, tool calls stay blocked, and it is executed at the next turn end — the agent resumes with the checkpoint summary instead of silently unbounded growth.
   - Never persisted: `isBusy` / `isCompacting` (an interrupted compaction is always safely retriable) and the idle clock (reset at every `session_start`).
   - State is cwd-scoped: resuming the session file from a *different* working directory starts from a fresh memory file by design.
   - A corrupt memory file degrades to safe defaults (disabled, tools hidden), never to a crash or a half-loaded state.
   - Covered by `extensions/self-propagate.test.mjs` (boot → kill → reboot against the same workspace, plus the goal lifecycle: seed → user override → agent rewrite approve/reject → clear → reset, and the interactive enable-time flow (keep/edit/skip)), wired into `npm test`.

### Tooling Surface

- **Commands:** a single entry point, `/self-propagate` (bare = help + current state): `on [here]` · `off` · `status` · `budget <0.3-0.95>` · `wake <once|every> <minutes>` · `wake off` · `goal [show|set|clear|reset|here|draft]` · `compact` · `help`. Subcommands and arguments tab-complete. One wake concept, two strengths: `once` fires a shrink steer once per idle streak when the prefix is 10k+ above the post-compact floor, `every` keeps it awake (and the tick carries the same pressure check); `wake every` takes precedence.
- **Cache economics (local models).** Every byte of the request head (system prompt + tool schemas) that changes busts the prefix cache — on local Apple-Silicon inference a cold re-read of the current prefix is minutes of compute, so the design minimizes head churn: the protocol block is static apart from the ceiling line (model/budget switches only), volatile budget telemetry rides per-turn appended messages, compaction is a full-wipe whose only new bytes are the agent's own checkpoint, and any sleep happens on a prefix at or below floor+10k (wake_defer auto-shrinks otherwise), so an eviction mid-sleep is a cheap re-read. The remaining intentional busts: tool set on enable/disable/reload, the one-shot goal nudge, each compaction's new summary, and the one *planned* bust a long deferral triggers when the prefix is fat. Telemetry stays lean on purpose: messages exist only at tick-fires and tool calls (1-2 lines each) — never per-turn bloat.
- **Tools:** `self_compact`, `memory_store`, `goal_set`, `wake_defer` — declared only while enabled. `goal_set` is hard-blocked like the other tools while a compaction is queued or the grace lock is engaged, and every applied goal change requires explicit user confirmation. `wake_defer` is the one tool the agent can use on the wake watchdog; it never changes the user's configured cadence, only silences it until the deferral expires or the user re-configures.
- **Renaming:** the extension used to ship `/propagate`, `/keep-awake`, `idle` and the `pin` subcommand; they are now subcommands of `/self-propagate` (`wake every` / `wake once` / `goal` respectively). Old command names no longer resolve. The internal checkpoint tag remains `<pinned_context>` (an internal wire format, renamed concept only).

### Why Pi's own system prompt needs no pinning (and where the cache really goes)

**How pi handles the prompt across compaction.** Pi rebuilds the system prompt from *current* resources on every run and diffs it against the sections recorded in the transcript; changed or removed sections are patched in as system messages, and system messages before any kept range are dropped at compaction (a fresh snapshot is replayed via the compaction entry). Extension/tool changes flow through the same diff (`toolsAdded`/`toolsRemoved`), and the loadout is restored from the branch on resume. Reloading an old session therefore picks up the new pi prompt, new extensions and new tools automatically.

**What the cut costs in the cache — exactly.** The cut is implemented as a per-request elision, not as a session rewrite: pi sends system prompt + tools + messages, and the `context` hook replaces the pre-cut body with one `compactionSummary` message carrying the checkpoint. Prompt caches are prefix-based, so the parts of the request *before* the first differing byte survive: with a stable head, the tool schemas + system prompt stay cached across the cut, and the cache diverges at the checkpoint summary. The unavoidable loss: the entire pre-checkpoint conversation body is replaced, so everything after the system block is a fresh read — true of *any* compaction, including pi's built-in one (which is actually *luckier*: it keeps the most recent ~20k tokens verbatim, pushing the divergence point further right and preserving more prefix). A full-wipe cut can never do better by construction; the only honest levers are keeping the head byte-stable — that is why the extension protocol block is a constant and all volatile budget telemetry is delivered as per-run custom messages — and keeping the anchor verification cheap (a single endsWith over the anchor message per request).

**Things the agent should know, verified against pi 1.5.2 source:**

- Pi's built-in summarizer is bypassed for `self_compact` checkpoints (`fromExtension: true`); it is also separately cache-safe when it does run: the summary request uses its own `SUMMARIZATION_SYSTEM_PROMPT`, the conversation as a single serialized user message, and `cacheRetention: "none"` (one-off prompts never write prompt cache). The session prompt is never touched by it.
- The summarization call uses the session's own model (`this.model` via the same auth chain), not a separate utility model — unless you configure pi's virtual-model routing, in which case it resolves a physical model from the virtual selection.
- Pi's `/compact` and overflow recovery use the same machinery; the extension cancels `threshold` compactions with no pending checkpoint but cannot intercept a manual `/compact` or an `overflow` — both lose the goal, KV and agent summary (documented in §3).
- Reloading a session against a *different* pi version or extension set: the head changes once (sections diff), everything re-caches, and it is stable again thereafter. Sections-diff patches keep mid-conversation-system-message models' cached prefix; models without that get one replay miss per *change* (not per turn).

**What the session file keeps.** Everything: `messages`, `compaction`, `context_edit`, model/thinking-level changes. Diffing/review tooling on the raw file sees the pre-compaction history forever; the checkpoint is additive metadata, not a splice.

**What self-propagate freezes, and what it scrubs.** Self-propagate checkpoints freeze three things: the session goal, the KV working memory and the agent's summary — all agent- or user-authored, all explicit. Pi's system prompt is never frozen. Agent/user content that enters the checkpoint is scrubbed of checkpoint- and steering-shaped tags (`<pinned_context>`, `<working_memory>`, `<compaction_summary>`, `<note>`, `<self_propagation_compaction_failed>`, etc.) on the write paths (goal set/seed/`goal_set`) and again at render time (KV bodies/titles, summary), so forging a checkpoint or a fake failure notice from inside the session means getting the user to approve literally that text. The remaining soft spots are cosmetic at worst: `budgetRatio` and other hand-edited scalars are not range-validated on load, and there is no append-only audit log of mandate rewrites yet.
